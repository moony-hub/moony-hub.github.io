这次实验做两件事：先用网络空间测绘引擎看看互联网上到底暴露了哪些东西，再用被动、主动两类手段收集子域名。所有检索都只针对公开数据和已授权目标。

<!--more-->

## 一、测绘搜索引擎在测什么

普通搜索引擎（百度、Google）检索的是**网页文本内容**；网络空间测绘引擎检索的是**互联网上联网的设备与资产**——IP、开放端口、服务指纹、操作系统、地理位置、证书。它内置主机测绘（Xmap）和 Web 测绘（Wmap）两类引擎，用专属语法检索公网资产。

ZoomEye（钟馗之眼）是知道创宇 404 安全实验室的产品，同类引擎还有：

| 引擎 | 归属 | 备注 |
| --- | --- | --- |
| ZoomEye | 知道创宇 404 实验室 | 国内，主机 + Web 测绘 |
| FOFA | 白帽汇 | 国内，语法灵活 |
| Quake | 360 鹰图 | 国内 |
| Hunter | 奇安信 | 国内 |
| Shodan | 国外 | 最早的设备搜索引擎之一 |
| Censys | 国外 | 证书与主机数据 |

常用的检索字段：

| 语法 | 作用 | 示例 |
| --- | --- | --- |
| `country:` | 国家 / 地区 | `country:CN` |
| `port:` | 开放端口 | `port:88` |
| `service:` | 服务名称 | `service:telnet` |
| `app:` | 应用指纹 | `app:nginx` |
| `domain:` | 某主域名下的资产 | `domain:example.com` |

> 法律提醒：测绘检索只允许用于自己拥有、或已获得授权的资产。未经授权登录、访问、渗透他人公网设备，属于网络违法行为。

## 二、实操：`port:88` 能看到什么

登录 ZoomEye，在搜索框输入：

```text
port:88
```

检索全网开放 88 端口的公网资产，本次返回约 **874 万条**结果。结果页可以看到公网 IP、归属地、开放端口、服务类型和 Banner 响应内容。

- 一部分主机的 88 端口跑的是 **Kerberos 认证服务**（Windows 域环境的典型端口）；
- 另一部分是 **Web 服务**，Banner 返回 `HTTP/1.1 403 Forbidden`，服务在，但目录不可直接访问。

这说明很多服务器会把非标准 Web 端口直接暴露在公网，配置不当就会带来信息泄露、未授权访问等风险。

### 一个有意思的对照

前期用 `country:CN service:telnet` 检索国内 Telnet 服务，结果是 **0 条**。原因不难理解：Telnet 明文传输账号口令，风险极高，国内公网环境基本已不再对外开放。这类"暴露面为零"的结果，反过来恰好说明基础安全加固的普及程度。

## 三、子域名收集的三条路

子域名是主域名下的分支域名，比如 `www.baidu.com`、`pan.baidu.com` 都是 `baidu.com` 的子域名。收集子域名是渗透测试信息收集阶段的基础工作，手段分**被动收集**和**主动 DNS 爆破**两类。

### 方法 1：ZoomEye 被动收集（本次实操）

检索语法：

```text
domain:baidu.com
```

注意语句里**不要加双引号**，直接输入即可。这样检索的是归属在 `baidu.com` 下、已被 ZoomEye 扫描收录的公网资产，可以从主机信息、证书标签里提取 `xxx.baidu.com` 形式的子域名。本次检索得到约 **133,026 条**资产记录。

- ✅ 优点：纯被动信息收集，不主动向目标服务器发送探测包，风险低，和前面的测绘实验连贯。
- ❌ 缺点：结果依赖 ZoomEye 的数据库收录情况，收集不全，需要搭配其他工具补充。

### 方法 2：证书透明度查询（crt.sh）

网站申请 SSL 证书时，证书会记录关联的子域名，而且这些记录公开可查。打开 <https://crt.sh>，输入主域名，就能批量查出证书里包含的子域名，收集效果通常比测绘平台更全面。

同类被动工具：Subfinder、Sublist3r，底层聚合了 ZoomEye、FOFA、VirusTotal、crt.sh 等多个数据源。

### 方法 3：主动 DNS 爆破

代表工具：OWASP Amass、Gobuster。原理是读取子域名字典，自动拼接 `xxx.baidu.com` 逐个向 DNS 服务器查询，验证子域名是否存在解析记录。

⚠️ 缺点是会发送大量 DNS 请求，容易触发目标防护策略，**只能用于已授权的域名测试**。

## 四、被动 vs 主动

| | 被动收集 | 主动爆破 |
| --- | --- | --- |
| 数据来源 | 测绘平台、证书、公开数据 | 自建字典逐个查询 |
| 是否接触目标 | 否 | 是（大量 DNS 请求） |
| 隐蔽性 | 高 | 低 |
| 覆盖率 | 取决于数据源 | 取决于字典质量 |
| 适用阶段 | 前期侦察 | 已授权目标的补充探测 |

## 五、小结

- 测绘引擎能快速看清一台设备、一个网段在公网上的暴露面：端口、服务、Banner 一目了然。
- 子域名收集没有银弹：ZoomEye 适合和测绘联动做被动收集，crt.sh 补证书维度，字典爆破补遗漏。
- 高危明文协议（Telnet）在公网几乎绝迹，说明基础加固确实在普及。
